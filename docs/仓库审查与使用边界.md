# 仓库审查与使用边界

> 审查日期：2026-10-16  
> 范围：当前 `main` 分支可见的脚本、JSON 模板、`SKILL.md`、`README.md` 与 TESNA 工作流。  
> 方法：静态阅读与 JSON 解析检查；**未在真实运行环境执行生图或完整端到端测试**。

## 1. 结论先看

- 当前仓库适合作为“工作流文档 + 提示词/布局模板 + 尚待环境适配的 Python 原型”。
- 它不是已经部署好的网页应用；GitHub 页面不能直接执行仓库里的 Python 脚本。
- 没发现明显重复的同名文件或重复版本副本；目前目录层级较少，暂时不建议大规模迁移。
- 5 个 JSON 模板均可成功解析。
- 发现几项可能影响真实使用的问题，详见下文。在这些问题修复并通过测试前，不建议把脚本生成结果直接作为正式上架素材。

### B. 需要配置环境后才能尝试

| 内容 | 需要什么 | 当前限制 |
|---|---|---|
| `scripts/generate_all.py` | Python 环境、Pillow、产品图片文件、可写输出目录 | 默认输出路径写死为 `/workspace/ec-visual-generator/output` |

## 3. 静态审查发现的问题

### 高优先级：正式使用前应处理

1. **产品原图可能被拉伸变形。** 在 `generate_all.py` 中，首图处理使用 `img.resize(dims)` 直接把原图拉到目标尺寸，没有按比例缩放或留白。产品图不是目标比例时，形状会改变。这与 TESNA 工作流中“产品外观优先、不得失真”的要求冲突。
2. **模板包含未经产品核实的功能宣称。** `templates/pain_points.json`、`templates/selling_points.json` 有主动降噪、ENC、快充、低延迟等示例；这些只能是参考内容，不能自动写入具体 SKU 的正式素材。
3. **脚本写入固定售后承诺。** `generate_all.py` 中的详情页售后模块直接写入“7天无理由退换、15天质量问题免费换新、1年质保、全国联保”等文字，未读取产品或店铺实际政策。正式输出前必须改为读取已确认的售后资料，或默认留空/待确认。
4. **对比图有默认比较值。** 脚本会在部分参数缺失时使用“长续航”“蓝牙5.3”“普通”“蓝牙5.0”“较重”等默认描述。不能把这类占位值当成已验证的竞品事实。

### 中优先级：影响可移植性或预期一致性

5. **AI 生图脚本路径写死。** `scripts/ai_image_gen.py` 使用特定的 `/root/.codebuddy/plugins/cache/...` 路径，且通过 `uv run` 调用。建议后续改为环境变量/命令行配置，并在缺失时给出明确提示。
6. **默认输出路径写死。** 主流程和文件整理器默认使用 `/workspace/ec-visual-generator/output`。跨电脑使用时应显式传入 `--output-dir`，后续再考虑改成相对于项目目录的默认路径。
7. **跳过 AI 的描述不够准确。** `--skip-ai-gen` 会为 AI 场景模块导出外部 Prompt，但主图/详情页中的 Pillow 合成模块仍会生成图片。应把它理解为“跳过内置 AI 生图调用”，而不是“完全不生成图片”。
8. **中文字体依赖环境。** `image_compose.py` 只尝试若干固定字体路径和 DejaVuSans 回退字体，实际中文显示需要在目标环境验证。

### 低优先级 / 后续工程化

9. 当前未发现专门的自动化测试文件、CI 流程或锁定依赖版本文件。
10. `templates/` 目前由 `prompt_builder.py` 以相对项目路径读取，保留该相对关系即可；当前没有足够依据要求迁移目录。
11. 当前仓库规模不大，`scripts/` 与 `templates/` 的分离是合理的。暂不建议为追求整齐而把脚本拆成更多层级。

## 4. 依赖清单说明

根目录 `requirements.txt` 只列出脚本直接导入的第三方 Python 库 Pillow。Python 标准库（例如 `json`、`pathlib`、`argparse`、`subprocess`）不需要写入依赖清单。

注意：安装 Pillow **不会**自动提供 nano-banana-pro 插件、`uv`、Gemini 服务访问权限或 API 凭据；AI 生图仍需要单独配置。当前没有在真实目标环境验证完整运行，因此不要把“依赖文件已补充”理解为“端到端已跑通”。

## 5. 建议的后续修复顺序

1. 修正产品原图缩放：保持比例、在目标画布中留白，不拉伸主体。
2. 移除售后承诺和对比图的硬编码默认值；没有已确认资料时标注“待确认”或不生成对应模块。
3. 将 nano-banana-pro 脚本路径改为可配置项，并在启动时检查路径和 `uv` 是否可用。
4. 将默认输出路径改为可移植路径，并验证 Windows/macOS/Linux 的字体表现。
5. 为 JSON 加入自动校验；为无 AI 模式增加轻量测试，再尝试完整端到端测试。

# TESNA 电商视觉工作流（标准版）

> 版本：v1.0  
> 用途：作为 TESNA 新品主图、详情页、场景图及营销视觉素材的统一执行规范。  
> 核心原则：**先确认产品事实，再规划视觉；先统一整套风格，再生成图片；逐张审核，不合格就修改。**

---

## 1. 工作流要解决什么问题

把新品资料转化为一套适合目标电商平台的视觉素材，减少图片风格不统一、产品外观失真、卖点编造、中文乱码、反复返工等问题。

工作流包含：
1. 产品资料整理与事实核对
2. 目标平台与图片规格确认
3. 受众、场景、痛点和卖点规划
4. 整套图片顺序与视觉风格规划
5. 图片生成与产品参考图约束
6. 单张审核、反馈和修改
7. 文字排版、图片检查与导出
8. 项目归档，为后续 SKU 和新品复用经验

**这是一套可在 ChatGPT 对话中执行的标准流程，不代表已部署成全自动软件。** 生图能力、图片数量、导出能力取决于当前使用的平台与工具；产品准确性和营销合规性仍需人工审核。

---

## 2. 开始一个新品项目时，需要提供什么

### 必需资料
- 产品名称 / 型号
- 产品真实图片：尽量提供清晰的正面、侧面、背面、接口、佩戴或使用图
- 目标平台：例如抖音商城、淘宝 / 天猫、京东、亚马逊
- 本次任务：主图、详情页、场景图、佩戴图、功能图或整套素材
- 已确认的产品参数与卖点
- Logo、品牌规范或既有视觉参考（如有）

### 可选资料
- 目标人群与典型使用场景
- 竞品参考图
- 价格带、活动信息和转化目标
- 指定颜色、字体、构图、禁用元素
- 平台图片规范或店铺现有素材

### 资料不足时的规则
- 不猜测未知参数，不把推测写成产品事实。
- 对降噪等级、蓝牙版本、防水等级、续航时间、音频编码、认证等具体描述，必须以已确认资料为准。
- 关键资料缺失时先询问；非关键资料可使用不涉及事实承诺的通用视觉方案。
- 未发布新品素材应注意隐私，不要随意上传到不清楚数据处理方式的第三方网站。

## 3. 完整执行流程

### 第 1 步：产品资料与外观基准
建立本次项目的产品事实清单：
- 产品外观、结构、材质、颜色
- Logo 的位置、形状与颜色
- 已确认的参数和功能
- 可宣传的卖点及其证据
- 禁止修改或不可编造的内容

**输出：产品基准。** 后续生成图片以该基准和用户提供的真实图片为准。

### 第 2 步：确认平台和输出规格
每次新品项目开始时，先由用户说明目标平台。

根据平台、图片用途和实际发布位置确定：
- 图片比例与像素尺寸
- 主图、详情图、SKU 图或广告图的用途
- 单张图片还是长图 / 合集
- 文件格式和导出要求

不要默认所有平台都使用同一尺寸。若规格不确定，先确认或采用明确标注的暂定规格，不能把暂定值说成平台官方要求。

### 第 3 步：确定受众、场景和卖点
围绕真实产品信息规划：
- 目标用户是谁
- 用户在什么场景中使用
- 用户关注的需求或痛点是什么
- 产品哪些已确认的特征可以回应这些需求
- 每一条宣传文案是否有事实依据

卖点链路建议使用：

**用户需求 → 产品特征 → 用户价值 → 支撑证据**

没有证据的具体参数或性能承诺，不进入正式图片文案。

### 第 4 步：规划整套图片顺序
根据平台与产品选择所需内容，不强制每个项目都使用同样数量。

耳机详情页可按需选择以下模块：
1. 首屏：产品与核心定位
2. 产品外观 / 整体展示
3. 佩戴效果与舒适性
4. 音质或声音体验
5. 降噪 / 通话功能
6. 操作方式与连接功能
7. 结构、材质、接口和细节
8. 续航、充电或其他已确认参数
9. 多场景使用
10. 包装、配件、售后或品牌收尾

以上是可选模块，不代表 Free7S 已具备其中所有功能。只展示有资料支持的内容。

**输出：图片清单。** 每张图写清楚目的、画面主体、核心信息、文案和需要避免的问题。

### 第 5 步：锁定整套视觉风格
在开始生成前，确定一套可复用的视觉规范：
- 品牌气质与整体风格
- 主色、辅助色、背景材质
- 光线、阴影和产品质感
- 构图、留白和信息层级
- 标题与正文的字体方向
- 图标、线条和分隔方式
- 产品图、文字与背景的比例关系

允许不同内容使用适合它的场景，但整套图要保持品牌一致性。不要为了统一而让每张图都使用完全相同的构图。

### 第 6 步：生成图片
每张图片生成时：
- 使用用户提供的真实产品图作为参考
- 明确说明必须保留的外观、结构、Logo 和颜色
- 说明本张图的用途、场景、构图、光线和视觉规范
- 不让模型自行增加未确认的按钮、接口、配件或功能
- 避免将复杂中文、Logo 或精密参数完全交给模型直接绘制

两种执行方式：
- **逐张确认模式（默认）**：先生成第一张，用户确认或提出修改后，再继续下一张。
- **合集草案模式**：一次生成多格视觉合集，用于快速比较风格和规划内容。合集只用于方案预览，不应直接当作最终独立详情图交付；需要拆分或重新生成单张，并逐张审核。

### 第 7 步：审核和修改

#### 产品准确性
- [ ] 产品轮廓、比例和部件与参考图一致
- [ ] 颜色、材质、接口、按键及耳机结构没有明显变化
- [ ] Logo 没有被改形、错拼或移位
- [ ] 没有凭空增加产品功能、配件或认证标识

#### 文案准确性
- [ ] 中文可读，没有乱码或错字
- [ ] 型号、参数、单位和标点正确
- [ ] 每项性能描述均有已确认资料支持
- [ ] 没有未经证实的降噪、续航、防水、音质等承诺

#### 视觉与平台适配
- [ ] 风格与本项目的视觉规范一致
- [ ] 产品主体足够清晰，没有被文字或装饰遮挡
- [ ] 文字层级、留白和阅读顺序合理
- [ ] 比例、尺寸与目标用途匹配
- [ ] 不同详情图之间没有明显的风格断裂

不合格时，指出具体问题并修改；不因“整体差不多”而跳过产品与文案检查。

### 第 8 步：后期排版与导出
建议将 AI 主要用于场景、氛围、构图草案和视觉素材；重要文字、Logo、型号、参数及图标尽可能使用可控的排版工具完成或复核。

导出前检查：
- 文件尺寸与比例
- 清晰度、边缘和压缩情况
- 文案、Logo 和参数
- 图片顺序与命名
- 单张文件是否独立可用
- 是否符合平台当时有效的上传规范

具体导出能力取决于当前工具；若当前环境无法直接完成拆图、排版或批量导出，应明确说明并采用可用的后期工具，不假设自动化已经实现。

### 第 9 步：归档和复用
建议每个新品项目使用以下目录：

```text
产品型号/
├── 01_产品原图/
├── 02_产品资料与参数/
├── 03_视觉方案与图片清单/
├── 04_生成草稿/
├── 05_审核修改/
├── 06_最终导出/
└── 07_复盘与版本记录/
```

文件命名建议：`型号_图片序号_图片用途_版本_尺寸`

示例：`Free7S_01_详情首屏_v01_平台规格.png`

保留原图、草稿和最终文件，避免覆盖源素材。复盘时记录哪些视觉方案可复用、哪些问题反复出现，以及实际运营数据（若有）。

## 4. TESNA Free7S 本次测试的具体规则

本次已确认：
- 产品：TESNA Free7S
- 目标平台：抖音商城
- 参考素材：用户提供的两张 Free7S 产品图
- 已测试视觉方向：黑色科技感、黑金点缀、白线分隔的详情合集
- 用户反馈：希望输出为正方形；合集包含卖点场景、佩戴、降噪、功能、结构等内容；当前生成图细节存在一定变形，但整体方向可参考

### 本次特别注意
1. **合集是视觉草案，不是最终交付。** 需要将每个模块作为独立图片生成或处理，再逐张审核。
2. **产品外观优先。** 耳机本体、充电盒、Logo、金色边框等以原图为准；若模型变形，必须修改或用真实产品素材重新合成。
3. **功能不能凭空添加。** 蓝牙版本、ENC / ANC、IPX 防水等级、续航、快充、低延迟等，只有在用户提供并确认后才能写入正式详情图。
4. **当前未确认的功能不视为 Free7S 的既定参数。** 之前合集中的具体数值和功能图标仅能作为待核对的视觉草案，不应直接用于上架。
5. **默认先做一张、确认后再继续。** 用户明确要求一次性合集时，可先做合集草案，但仍需确认后再进入单张精修。

## 5. 当前能力边界

这套工作流目前能够做到：
- 根据用户资料规划图片内容与顺序
- 建立可复用的视觉风格规范
- 编写每张图的生成要求并调用当前可用的生图能力
- 根据反馈逐张调整
- 用审核清单降低产品变形、文案错误和风格不统一的风险

目前不能保证：
- AI 每次都准确还原精密产品结构
- 生图模型准确生成复杂中文、Logo 和小字
- 所有图片自动满足所有平台的最新规格
- 未经测试就实现批量自动生图、自动拆图、自动排版或自动上传
- 仅凭图片就验证产品性能、认证或真实营销效果

如果当前网络环境不支持 Codex 或 apiz CLI，流程仍可在当前对话中进行策划与生图（以当前可用工具为准）；不能把依赖这些服务的 GitHub 项目视为已经可用的执行工具。

## 6. 新品项目启动模板

每次开始新品时，可复制并填写：

```text
开始 TESNA 新品电商视觉项目。

产品名称 / 型号：
目标平台：
本次任务：主图 / 详情页 / 场景图 / SKU 图 / 整套视觉方案
产品原图：已上传 / 待上传
已确认参数：
已确认卖点：
目标人群与使用场景：
品牌风格或参考图：
输出尺寸：按平台和用途确认
其他要求：

执行规则：
1. 先检查资料完整性，必要时只问关键问题。
2. 未提供的参数、功能、认证不得编造。
3. 产品外观、颜色、Logo 以真实参考图为准。
4. 先给出图片清单和视觉方向。
5. 默认逐张生成；每张等待我确认后再继续。
6. 若做合集，先作为视觉草案，之后仍需独立审核每张图。
7. 文字、Logo、参数优先确保准确和可读。
8. 通过审核后再按目标平台要求导出。
9. 不增加非必要步骤，不把尚未实现的自动化描述成已实现。
```

## 7. 工作流总览

```text
产品原图与真实资料
        ↓
核对产品事实与硬性约束
        ↓
确认目标平台、用途与尺寸
        ↓
受众 / 场景 / 痛点 / 已证实卖点
        ↓
图片清单与内容顺序
        ↓
统一视觉规范
        ↓
逐张生图或先做合集草案
        ↓
检查产品、Logo、文案、功能与尺寸
        ↓
修改 / 重新生成 / 后期排版
        ↓
最终导出与项目归档
        ↓
复盘并复用到下一个 SKU
```

**最终原则：少加工具，先把流程跑顺；先保证产品真实，再追求视觉高级；先完成可用素材，再逐步自动化。**
